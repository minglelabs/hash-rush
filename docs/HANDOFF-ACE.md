# 인수인계: 초고수 봇 강화 (2026-10-12)

**목적: 초고수(`ace`)가 고수(`hard`)를 압도하게 만든다.** 초보·중수·고수는 그대로 둔다.

이 문서는 작업 지시서다. 아래 내용은 코드를 읽고 측정한 결과이고, **구현은 아직 하나도 하지 않았다.**
기준 커밋은 `main` `a57d456` (#106).

## 1. 지금 초고수의 구조

| 무엇 | 위치 | 내용 |
| --- | --- | --- |
| 설정 | `src/ai/bot.js` `DIFFICULTY.ace` | `{ ...hard, search: true, dance: true, poach: 2, wary: 0.5 }`. 손(반응 0.12초, 조준, 사거리)은 고수와 같다 |
| 규칙 | `src/ai/bot.js` `plan()`, `engage()`, 던지기, 꿀밤 판단 | 모든 난이도가 같이 쓰는 코드. 초고수 전용 분기는 `cfg.dance`, `cfg.wary`, `cfg.poach`, `cfg.search` |
| 미리보기 | `src/ai/search.js` | 0.3초마다 계획 몇 개를 게임 사본에서 2.4초씩 돌려 `judge()` 점수가 높은 것을 고른다 |

미리보기가 고르는 것은 **어디로 갈지(모드·목표·경로)뿐**이다. 싸움, 던지기, 갉기 같은 세부 동작은 규칙이 한다.
규칙의 계획(`rules`)은 항상 후보에 들어가고 60점 덤을 받는다(`SEARCH.edge`).

### 결론

초고수는 **싸움만 강하고 씨 운영은 고수보다 못하다.** 승리의 대부분이 타임오버 꿀밤 수 승부이고,
골인 전환율은 고수의 절반이다. 압도하려면 씨 운영을 고치고, 타임오버 승부를 의도적으로 가져가야 한다.

## 4. 작업 항목

효과가 클 것으로 보는 순서다. 전부 **초고수 전용 설정으로만** 켠다(6절).

### 4.1 갉기 타이밍

- **문제**: 갉는 데 2.2초(4인 기준, `gatherTime`)가 필요한데 판당 21초를 서 있고 0.57개만 얻는다. 움직이면 처음부터,
  꿀밤을 치면 줄 맨 뒤로 가는 규칙 때문에 중간에 끊긴다. `judge()`가 갉는 중이면 점수를 줘서(`160 * me.gather`),
  상대가 1초 거리에 있어도 서서 갉는다.
- **할 일**:
  - 상대별 "해바라기 도착 예상 시간"을 계산한다(맞고 둥지에서 돌아오는 시간 포함. 둥지에서 해바라기까지 미로로 4초 이상).
  - 가장 빠른 상대의 도착이 남은 갉기 시간보다 늦을 때만 갉는다.
  - 빠르면 링 밖으로 나가 먼저 잡는다. 잡힌 상대가 돌아오는 시간이 갉기 시간보다 길다는 것이 핵심이다.
  - "근처 둘을 연달아 잡고 갉기"를 미리보기 계획으로 추가한다.

### 4.2 던지기 절제

- **문제**: 얻은 씨의 48%를 던진다. 고수의 확률(`toss: 0.5`, `volley: 1`)을 그대로 물려받았다.
- **할 일**: 초고수는 확률 주사위를 쓰지 않는다. 던지는 경우를 다음으로 한정한다.
  - 둘 이상이 맞을 때
  - 상대 씨 운반자가 맞을 때
  - 앞뒤로 막혀 어차피 잡힐 때
  - 4.4의 점수판 계산상 꿀밤 1점이 승부를 가를 때
- 가능하면 "던지기 / 맞서기 / 기다리기"를 미리보기 계획으로 넣어 비교하게 한다.

### 4.3 집으로 가는 길

- **문제**: 씨를 든 계획은 "지금 위치 기준으로 덜 위험한 입구 3곳"을 2.4초만 돌린다. 집까지 4초 넘게 걸려 끝을 못 본다.
  위험 비용(`danger`)은 상대의 현재 위치만 보고, 상대가 문 앞으로 모이는 것을 모른다.
- **할 일**:
  - 씨를 든 계획은 집에 닿거나 맞을 때까지(상한 약 6초) 돌린다.
  - 계획 추가: 길이 빌 때까지 기다리기, 갈림길에서 다른 길로 바꾸기, 굴 근처로 물러나기.
  - 수비 봇은 "운반자에게 가장 가까운 입구"를 예측해 문 앞을 막는다(`intercept`). 한쪽으로 가는 척하다 바꾸면 통한다.

### 4.4 시계와 점수판: 승리만을 위해, 선 없이

요청 사항이다. **재미나 보기 좋음은 고려하지 않고 승률만 최대화한다.** 싸움으로 이기든 골인으로 이기든 상관없다.

알아야 할 규칙(`src/sim/game.js`, `src/sim/constants.js`):

- 40초부터 집 경계가 초당 6.5px씩 해바라기 쪽으로 넓어지고(`OVERTIME`), 한계는 해바라기 위치다. 105초에 판이 끝난다.
- 타임오버 승자는 **꿀밤 수(꿀밤 + 던져서 잡은 수)**, 같으면 **덜 맞은 쪽**, 같으면 **씨를 더 많이 문 쪽**, 그래도 같으면 공동 승리다
  (`timeoutRanking`). 팀전은 팀 합계다.
- **집 안에서는 맞지 않는다**(`inHome`). 씨 없는 햄스터가 집에 머무는 것을 막는 규칙은 없다.
- 골인은 언제든 즉시 승리다.

할 일:

- **이길 확률로 판단한다.** `judge()`의 꿀밤 15점, 내 죽음 −112점 같은 고정 점수를 남은 시간과 현재 순위에 따른 값으로 바꾼다.
  끝이 가까울수록 꿀밤 1개와 죽음 1번의 가치가 커진다.
- **앞서고 있을 때**: 꿀밤 수 1위이고 남은 시간이 짧으면 집 안으로 들어가 버틴다. 나오는 경우는 두 가지뿐이다.
  상대가 씨를 물었을 때(골인은 순위를 무시하고 진다), 다른 상대가 꿀밤 수를 따라잡을 때.
  후자는 안전한 표적(헛치고 굳은 상대, 갉는 상대)만 노린다.
- **뒤지고 있을 때**: 가장 쉬운 표적을 고른다. 난이도가 낮은 상대, 다른 싸움에 묶인 상대, 헛친 직후의 상대.
  둘이 싸우는 곳에 가서 굳은 쪽을 치는 것을 이동 계획으로 넣는다(지금은 사거리에 들어온 경우만 친다).
- **동률 관리**: 꿀밤 수가 같으면 덜 맞은 쪽이 이기므로, 동률이면 싸움을 피하는 쪽이 유리한지 계산한다.
- **막판 씨**: 연장 후반에는 집 경계가 해바라기 근처까지 와서 씨를 물면 1~2초에 골인이다. 막판에는 4.1의 "잡고 갉기"가
  곧 승리이므로, 80초 이후 해바라기 주변을 비우는 것을 최우선으로 둔다. 반대로 상대의 막판 갉기는 무조건 끊는다.
- **던지기는 꿀밤 점수**: 던져서 잡은 수도 꿀밤 수에 들어가고 한 번에 여럿을 잡는다. 막판에 뒤지고 있고 골인이 불가능하면
  씨는 점수용 무기다.
- **팀전**: 380판에서 타임오버가 없었으므로 위 내용은 사실상 개인전용이다. 팀전은 4.6을 본다.

### 4.5 미리보기 정확도

- **문제**: 가상 대결에서 나와 상대 모두 "사거리에 들어오면 바로 꿀밤"(`withBonk`)만 하고, 계획당 한 번만 돌린다.
  싸움 결과가 사실상 동전 던지기라 계획 비교가 흔들린다. 실제 초고수의 명중률(76%)도 반영되지 않는다.
- **할 일**: 계획당 여러 번(3~5회) 돌려 평균을 내거나, 가상 대결의 싸움을 실측 승률로 대체한다.
  다른 봇의 행동을 "가까운 씨 운반자 쫓기"가 아니라 실제 규칙(`plan()`)으로 흉내 내는 것도 검토한다.

### 4.6 팀전

- 같은 팀끼리 겹쳐 있으면 한 방에 같이 쓰러지는데(스플래시), 겹침을 피하는 코드가 없다.
- 호위와 두 번째 씨를 45% 주사위(`SECOND_SEED`)로 정한다. 위치와 미리보기로 정하게 바꾼다.
- 호위가 운반자 앞에서 길을 여는 대형(팀원은 서로 통과, 상대는 막힘)을 검토한다.

### 하지 않기로 한 것

반응 속도를 0.12초보다 줄이는 것. 사람 반응보다 이미 빨라서 추천하지 않았다. 다만 4.4의 "선 없이" 방침과 충돌하므로,
위 항목으로 목표에 못 미치면 다시 물어볼 것.

## 5. 측정 방법

`npm run sim`(`tools/simulate.js`)은 **골인으로 끝난 판만 승으로 센다.** 타임오버 승이 빠지므로 승률 비교에 쓰면 안 된다.
2절의 수치는 아래 스크립트로 냈다. 저장소 루트에 임시 파일로 두고 돌린 뒤 지웠다.

```js
// node _d.mjs 120 ace,hard,hard,hard
import { createGame, step } from './src/sim/game.js';
import { createBot } from './src/ai/bot.js';
const games = +process.argv[2];
const levels = process.argv[3].split(',');
const S = {};
const st = (lv) => (S[lv] ||= { n: 0, win: 0, goal: 0, timeW: 0, seeds: 0, lostBonk: 0, thrown: 0, deaths: 0, kills: 0, whiffs: 0, swings: 0, nib: 0 });
let timeUps = 0;
for (let n = 0; n < games; n++) {
  // 자리를 돌려서 어느 난이도도 같은 둥지에 머물지 않게 한다.
  const rot = levels.map((_, i) => (i + n) % levels.length);
  const g = createGame({ slots: rot.map((i) => ({ name: `b${i}`, kind: 'bot' })), seed: n + 1 });
  const lv = rot.map((i) => levels[i]);
  const bots = rot.map((i, s) => createBot({ difficulty: levels[i], seed: n * 97 + s * 13 + 5 }));
  while (g.phase !== 'over' && g.tick < 36000) {
    step(g, bots.map((b, i) => b.think(g, i)));
    if (g.nibbler >= 0) st(lv[g.nibbler]).nib++;
    for (const ev of g.events) {
      if (ev.type === 'seed') st(lv[ev.id]).seeds++;
      if (ev.type === 'bonk') { st(lv[ev.id]).deaths++; if (ev.seed) st(lv[ev.id]).lostBonk++; st(lv[ev.by]).kills++; }
      if (ev.type === 'throw') st(lv[ev.id]).thrown++;
      if (ev.type === 'impact') { st(lv[ev.id]).swings++; if (!ev.hit) st(lv[ev.id]).whiffs++; }
    }
  }
  if (g.timeout) timeUps++;
  for (const l of lv) st(l).n++;
  for (const id of g.winners) { const w = st(lv[id]); w.win += 1 / g.winners.length; if (g.timeout) w.timeW += 1 / g.winners.length; else w.goal++; }
}
console.log(`${games} games, time-ups ${timeUps}`);
console.table(Object.fromEntries(Object.entries(S).map(([l, s]) => [l, {
  'win/seat %': Math.round((s.win / s.n) * 100), goal: s.goal, timeUp: Math.round(s.timeW),
  'seeds/seat': +(s.seeds / s.n).toFixed(2), 'seed→goal %': Math.round((s.goal / (s.seeds || 1)) * 100),
  'seed thrown %': Math.round((s.thrown / (s.seeds || 1)) * 100), 'seed bonked %': Math.round((s.lostBonk / (s.seeds || 1)) * 100),
  kills: +(s.kills / s.n).toFixed(1), deaths: +(s.deaths / s.n).toFixed(1),
  'swing hit %': Math.round((1 - s.whiffs / (s.swings || 1)) * 100), 'nibble s': +(s.nib / 60 / s.n).toFixed(1),
}])));
```

팀전은 `createGame`의 슬롯에 `team`을 넣고 승리 팀으로 집계한다. 초고수가 든 판은 판당 2~3초 걸리므로
여러 대진을 프로세스로 나눠 동시에 돌리면 10분 안에 끝난다.

## 6. 지켜야 할 것

- **초보·중수·고수는 그대로.** 모든 변경은 `DIFFICULTY.ace`에만 있는 설정으로 켠다.
  `ace`는 `{ ...DIFFICULTY.hard }`로 고수를 물려받으므로, 고수 값을 건드리면 초고수도 바뀌고 반대는 아니다.
- **난수 순서를 건드리지 않는다.** 봇마다 `rng()`를 순서대로 쓰므로, 공용 경로에 `rng()` 호출을 넣으면 다른 난이도의 행동도
  바뀐다. 초고수 전용 분기 안에서만 호출한다(`cfg.x && rng()`처럼 앞에서 걸러지게).
- **검증**: 봇 시뮬레이션은 결정적이다. 초보·중수·고수만 넣은 대진의 출력이 수정 전후 **완전히 같아야** 한다.
  예: 위 스크립트로 `easy,normal,hard,hard`, `hard,hard,hard,hard`를 수정 전후로 돌려 비교한다.
- **계산량**: 봇은 방장의 브라우저에서 돈다. 지금 초고수는 0.3초마다 계획 약 8개를 144틱씩 돌린다.
  4.3(더 긴 미리보기)과 4.5(여러 번 돌리기)는 이것을 몇 배로 늘린다. 초고수 7마리를 폰에서 돌려도 60fps가 유지되는지 잰다.
- **테스트**: `npm test`는 2분쯤 걸린다. 봇 관련 테스트는 `test/game.test.js`에 있다.
